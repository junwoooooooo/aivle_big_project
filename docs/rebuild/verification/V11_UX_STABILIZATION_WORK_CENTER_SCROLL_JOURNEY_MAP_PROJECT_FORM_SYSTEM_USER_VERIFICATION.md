# V11 사용자 검증 안내

## 사전 조건

- 실제 로그인 가능한 사용자 계정
- 프로젝트 1개 이상
- 가능하면 작업 이력 20건 이상인 프로젝트와 작업 0건인 새 프로젝트 각각 1개
- 브라우저 확대 100%

자동 검증은 15개 파일·48개 테스트, 변경 파일 ESLint, 프로덕션 빌드까지 통과했다. 아래는 인증된 실제 화면에서만 확정할 수 있는 최종 Live 항목이다.

## 1. 프로젝트 전체 스크롤

각 메뉴에서 콘텐츠가 화면보다 길도록 열고 마우스 wheel, trackpad, PageDown을 각각 확인한다.

- 사업 기획
- 사업 검증
- 출시 준비
- 가상 인터뷰
- 마케팅 전략
- 최종 보고서

합격 기준:

- Work Center를 사용하지 않은 일반 화면이 정상 스크롤된다.
- Full Work Center를 닫은 뒤 즉시 페이지 스크롤이 복구된다.
- 다른 프로젝트 메뉴로 이동한 뒤에도 스크롤이 잠기지 않는다.

## 2. Work Center Quick/Full

1. 상단 `작업`을 누른다.
2. Quick Panel이 하나만 보이는지 확인한다.
3. 현재 진행/입력 필요/최근 작업 metric의 너비가 panel 전체에 고르게 정렬되는지 확인한다.
4. `전체 작업 보기`를 누른다.
5. Quick이 사라지고 화면 아래에서 Bottom Sheet 하나만 올라오는지 확인한다.
6. header는 고정된 채 목록 영역만 스크롤되는지 확인한다.
7. X, Backdrop, Escape로 각각 닫고 페이지 스크롤을 확인한다.
8. 작업 상세의 `업무 화면 열기`를 눌러 overlay가 사라지고 경로가 이동하며 스크롤이 가능한지 확인한다.

합격 기준:

- Quick header와 Full header가 동시에 보이지 않는다.
- Full이 우측 Drawer 또는 Quick 내부 카드처럼 보이지 않는다.
- X/Backdrop/Escape/route 이동 후 overlay와 body 잠금이 남지 않는다.
- Tab/Shift+Tab이 열린 Full dialog 안에서 순환하고, 닫으면 상단 작업 trigger로 초점이 돌아온다.

## 3. Work Center 데이터 상태

- 새 프로젝트: `아직 실행한 작업이 없습니다.`와 안내 문구가 보인다.
- 작업 프로젝트: 현재 진행/입력 필요/전체 이력 수치와 필터가 보인다.
- 20건 이상: `이전 작업 더 보기`로 중복/누락 없이 추가된다.
- 상세: chevronLeft 아이콘, 작업명, 업무 화면 열기가 같은 header에 보인다.

## 4. Overview Journey

Desktop 1920×1080과 1440×900에서 확인한다.

- 왼쪽에서 오른쪽으로 1 → 2 → 3 → 4 → 5 → 6 순서다.
- station이 위아래로 자연스럽게 stagger된다.
- 곡선이 각 station 중심 또는 바로 옆을 통과한다.
- action은 흐름 화살표가 아니라 `arrowUpRight` 메뉴 열기 아이콘이다.
- 시작/계속/확인/업데이트/결과 보기 문구가 상태에 맞는다.

Mobile 390×844에서는 1~6이 세로 roadmap으로 표시되고 가로 스크롤이 없어야 한다.

## 5. 프로젝트 폼

Desktop에서 다음 대표 화면을 확인한다.

- Idea Intake
- 프로젝트 생성/사업 개요
- Concept 선택 이유/가설 수정
- Market 경쟁사 Seed/재수집
- Finance
- TechOps
- Twin 상황 문장
- Marketing 생성/copy/style/visual

합격 기준:

- 일반 입력 한 항목이 `[레이블] [컨트롤]` 한 행으로 보인다.
- 레이블 열과 컨트롤 시작선/폭이 일정하다.
- 설명과 오류는 컨트롤 열 아래에 위치한다.
- input/select 높이, textarea, hover/focus/disabled 표현이 일관된다.
- Mobile 390×844에서 레이블 위, 컨트롤 아래의 1열이며 가로 overflow가 없다.
- 체크박스 카드, 비교안, slider 같은 전용 선택 UI는 의미에 맞는 기존 구조를 유지한다.

## 6. 파일 Dropzone

Idea, TechOps, Marketing에서 각각 확인한다.

- 영역 클릭과 키보드 focus로 파일 선택이 가능하다.
- 파일을 drag over하면 강조 상태가 보인다.
- 선택 후 파일명/크기/제거 버튼이 보인다.
- 업로드 중에는 busy 문구와 비활성 상태가 보인다.
- 허용 형식 안내가 보이고 기존 API/검증 오류가 동일하게 동작한다.

## 8. 실패 시 기록할 정보

- 화면 크기와 브라우저 확대 비율
- 프로젝트 ID와 메뉴 경로
- Work Center 종료 방식(X/Backdrop/Escape/업무 화면 열기)
- Quick과 Full이 동시에 보이는지
- 스크롤 불능 시 `document.body.style.overflow` 값
- 문제가 보이는 화면 캡처

모든 표 항목이 통과한 뒤에만 V11 Live 검증을 최종 완료로 판정한다.
