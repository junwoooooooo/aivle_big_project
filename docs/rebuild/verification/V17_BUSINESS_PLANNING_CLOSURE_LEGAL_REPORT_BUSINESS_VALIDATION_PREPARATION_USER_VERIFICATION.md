# V17 사업 기획 마무리·법률 보고서·사업 검증 준비 사용자 검증

## 검증 상태

- 기능 자동 검증: 완료
- 사용자 시각/PDF 검토: 필요
- 권장 화면: 1920×1080, 1440×900, 390×844

## 1. 현재 선택으로 돌아가기

1. A 사업안을 선택해 기준값 화면으로 이동한다.
2. `선택 변경`을 누른다.
3. 현재 선택 A 카드의 `현재 선택으로 계속`을 누른다.

확인:

- 새 selection 요청이 발생하지 않는다.
- gallery가 접힌다.
- A 선택은 그대로다.
- 현재 서버 Decision 단계가 다시 보이고 포커스가 이동한다.

다른 B를 선택했을 때는 V16과 같이 서버 refresh 후 B가 현재 선택이 되고 gallery가 접혀야 한다.

## 2. Decision spacing과 이유 설명

- 단계 표시는 `사업안 선택 → 분석 기준 확정 → 법률·규제 확인 → 사업 검증 준비` 순서다.
- 선택 요약과 기준값 사이가 붙어 보이지 않는다.
- 기준값 요약과 법률 결과 사이가 붙어 보이지 않는다.
- 단계 안내에서 왜 기준값을 먼저 보고 법률 검토가 뒤에 오는지 이해할 수 있다.

## 3. 기준값 read/edit

### 시장 점유율

- read mode에 목표, 기간, 근거가 모두 보인다.
- 근거가 없으면 작은 `근거가 아직 없습니다.` 문구가 보인다.

### 초기 목표 시장 규모

- canonical 금액과 통화가 보인다.
- 그 아래 `5천만 원`, `1억 2천5백만 달러` 같은 한국어 읽기가 보인다.
- 기준 기간, 계산 기준, 근거가 편집하지 않아도 보인다.
- 통화 환산처럼 보이지 않아야 한다.

### 편집

- `수정`을 누르면 흰 surface, 미세 brand border/ring으로 편집 영역이 구분된다.
- heading에 `수정 중`이 표시된다.
- 기준값 확정 후 열린 editor가 닫히고 read mode로 돌아온다.

## 4. 기준값 확정 2단계

1. 값을 수정하고 `기준값 확정`을 누른다.
2. 처리 중 `기준값을 확인하고 있습니다...`를 확인한다.
3. 완료 후 `7/7 확인 완료`와 read mode를 확인한다.
4. `현재 값으로 진행`을 누른다.

확인:

- 첫 action은 hypothesis confirm만 수행한다.
- 두 번째 action이 법률 보고서를 준비한다.
- Delta 검토가 필요하면 기준값 화면에 남아 영향 확인 안내가 보인다.
- Delta 실패 시 기존 retry가 보인다.

## 5. 법률·규제 결과

`현재 값으로 진행` 완료 후 법률 화면에서 확인한다.

- 별도 `법률·규제 결과 확인 완료` 버튼을 누르지 않아도 보고서가 즉시 보인다.
- raw `IMPLEMENTABLE_WITH_CONTROLS` 대신 사용자 문구가 보인다.
- 일반 UI에 근거 hash와 기술정보 disclosure가 없다.
- 조항을 열면 `주요 내용`, 시행일, `법령 원문 보기`가 보인다.
- 법률·규제 header 근처에 `법률·규제 보고서 PDF`와 `시장 분석 준비하기`가 있다.

## 6. 법률 보고서 PDF

1. `법률·규제 보고서 PDF`를 누른다.
2. 전용 문서 route가 열리는지 확인한다.
3. `PDF로 저장`을 누르고 브라우저 print preview를 연다.

확인:

- app topbar, 프로젝트 header, substeps, 버튼 toolbar가 PDF에 나오지 않는다.
- A4 여백과 표지가 보인다.
- 프로젝트명, 선택 사업안, 사업 분야, 기준일, 보고서 ID가 맞다.
- numbered section 1~14가 출력된다.
- 같은 법률의 조항이 한 법률 아래 묶인다.
- 법률 제목과 첫 내용이 페이지 사이에서 부자연스럽게 분리되지 않는다.
- 공식 원문 link가 PDF에서도 클릭 가능하다.
- raw enum, hash, TaskRun, 기술정보가 없다.

이 기능은 직접 binary download가 아니라 Browser Save-as-PDF 방식이다.

## 7. 사업 검증 준비

1. 법률 화면에서 `시장 분석 준비하기`를 누른다.
2. 기존 BM 준비 revision이 있으면 값이 자동으로 채워지는지 확인한다.

화면 확인:

- 좌측에 고객 관계·활동·자원·파트너가 있다.
- 우측에 예산·기간·인원이 있다.
- 모든 항목이 선택 입력이다.
- 정확히 정하지 않은 숫자는 비워도 된다는 안내가 있다.
- BM Plan이 시장 분석의 AI input이라고 오해할 설명이 없다.

저장 확인:

- 값을 입력하고 `저장하고 계속`을 누르면 먼저 BM Plan이 저장된다.
- 저장 실패 시 시장 준비 handoff가 시작되지 않고 입력이 유지된다.
- 모두 비운 경우 `비운 채 계속` 확인 후 진행할 수 있다.
- 진행 중 raw event 대신 `사업 검증에 필요한 정보를 정리하고 있습니다.`가 보인다.
- 완료 후 네 단계 check와 `시장 분석 시작하기`가 보인다.

## 8. 이후 사업 모델 화면

### 준비 revision이 있는 경우

- 사업 모델에 처음 들어가도 전체 Plan form이 자동으로 다시 나오지 않는다.
- `사업 검증 준비에서 저장한 운영 정보를 사용합니다.` 안내가 보인다.
- `준비 정보 보기·수정`과 `캔버스 만들기`가 보인다.
- 수정 버튼으로 기존 값을 고칠 수 있다.

### revision 0인 경우

- 기존 optional 운영 정보 form에 접근할 수 있다.
- 빈 항목은 확인 후 그대로 진행할 수 있다.

## 9. 반응형

### Desktop

- 사업 검증 준비가 약 60~65% / 35~40%로 읽힌다.
- 법률 문서 screen preview가 지나치게 넓지 않다.

### 390×844

- 사업 검증 준비가 한 열로 전환된다.
- input과 button이 화면 밖으로 나가지 않는다.
- 시장 목표 structured read가 한 열로 쌓인다.
- 법률 header action과 PDF toolbar가 자연스럽게 쌓인다.
- 가로 overflow가 없다.
