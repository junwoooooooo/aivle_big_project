# V21.2 사용자 검증 안내

자동 기능 검증은 완료되었습니다. 아래 절차는 실제 Word와 Chrome/Edge 환경에서의 사용자 확인 항목입니다.

## 1. 기존 사용자 Finance DOCX 재업로드

1. 기존에 작성한 `finance-readiness-input.docx`를 수정하지 않고 그대로 업로드합니다.
2. Finance 분석이 시작되는지 확인합니다.
3. 결과에서 다음 값을 확인합니다.

- 연간 고정 인건비: 160,000,000
- 연간 임차·관리비: 24,000,000
- 연간 인프라 비용: 15,000,000
- 초기 개발·연구비: 90,000,000
- 초기 장비·인프라 비용: 20,000,000
- 초기 특허·라이선스 비용: 6,000,000
- 3개년 목표: 100 / 300 / 900
- 총 마케팅비: 30,000,000
- 총 영업비: 18,000,000
- 신규 고객 수: 5,000
- 수익 모델: HYBRID
- 단가: 500
- 월 구독 가격: 2,000,000
- 월 이탈률: 4.5
- 단위 변동비: 350
- 결제 수수료: 50
- 파트너 지급액: 0
- 배송비: 0
- 고객 증분 인프라 비용: 100

기대 결과: HTTP 422 없이 import되며, 괄호 안 산정 근거의 숫자가 계산값에 합쳐지지 않습니다.

## 2. 새 Finance 템플릿

1. 새 Finance DOCX 템플릿을 내려받습니다.
2. 각 항목에 `입력값`과 `산정 근거 · 선택` 셀이 따로 있는지 확인합니다.
3. 입력값에는 `160000000`, 산정 근거에는 `개발자 2명, 3~4인`을 입력합니다.
4. 문서를 업로드합니다.

기대 결과: 계산값은 160,000,000이고 산정 근거는 별도 사용자 근거로 보존됩니다.

## 3. PDF 미리보기

Technology, Operations, Finance 및 통합 보고서에서 각각 확인합니다.

1. `PDF 미리보기`를 누릅니다.
2. Dialog가 즉시 열리는지 확인합니다.
3. 준비 중 문구 뒤 PDF 페이지가 canvas로 표시되는지 확인합니다.
4. 미리보기 버튼만 눌렀을 때 파일 저장 창이나 자동 다운로드가 발생하지 않는지 확인합니다.

기대 결과: 브라우저 기본 PDF iframe이 아니라 PDF.js canvas가 최소 1페이지 이상 표시됩니다.

## 4. 명시적 PDF 다운로드

1. 미리보기가 열린 뒤 `PDF 다운로드`를 누릅니다.
2. 저장된 파일을 Chrome/Edge 또는 PDF reader로 엽니다.

기대 결과: 이 버튼을 누른 경우에만 저장이 시작되며, 저장된 파일이 정상 PDF로 열립니다.

## 5. 오류 문구 구분

가능한 테스트 환경에서 각 실패를 재현합니다.

| 상황 | 기대 문구 | 다운로드 버튼 |
|---|---|---|
| 서버/네트워크 fetch 실패 | 보고서를 불러오지 못했습니다. | 없음 |
| PDF가 아닌 bytes 응답 | 생성된 보고서 형식을 확인할 수 없습니다. | 없음 |
| 유효 PDF이지만 PDF.js 렌더 실패 | 보고서는 생성되었지만 미리보기를 표시하지 못했습니다. | 있음 |

세 오류가 하나의 일반 문구로 합쳐지지 않아야 합니다.

## 6. 독립 실행 회귀

Market/BM 결과가 없는 새 프로젝트에서 각각 확인합니다.

- Technology DOCX 업로드 및 분석
- Operations DOCX 업로드 및 분석
- Finance DOCX 업로드 및 분석

기대 결과: 세 모듈 모두 다른 분석 결과를 선행 조건으로 요구하지 않고 독립 실행됩니다. 기존 Work Center에서 TaskRun과 JobEvent를 계속 확인할 수 있어야 합니다.
