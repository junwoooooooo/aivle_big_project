# V18 사용자 검증 가이드

## 검증 상태

- 자동 기능 검증: COMPLETE
- 실제 인증 화면 디자인 검토: USER REVIEW PENDING
- 권장 화면: 1440×900, 1920×1080, 390×844

## 1. 사업안 실행 상세와 진행 단계

1. 사업안 생성이 진행 중인 프로젝트를 연다.
2. 단계가 `아이디어 조건 확인 → 사업안 탐색·구체화 → 법률·규제 검토 → 결과 정리` 네 개로 보이는지 확인한다.
3. 법률 검토 후 다른 후보를 다시 구체화하는 로그가 와도 화면 단계가 탐색으로 돌아가지 않는지 확인한다.
4. 실행 초기에 `0개 사업안`, `추가 검토 0건`이 보이지 않는지 확인한다.
5. summary 도착 후 `5개 검토 · 1개 준비 · 2개 추가 확인`처럼 실제 수만 보이는지 확인한다.
6. `작업센터에서 상세 기록 보기`를 누른다.
7. 기존 Work Center Bottom Sheet가 열리고 해당 job 상세가 바로 표시되는지 확인한다.

## 2. 사업안 수와 비교

1. 준비된 사업안이 1개인 상태를 연다.
2. 비교 picker와 `비교에 추가` checkbox가 모두 없는지 확인한다.
3. 사업안이 2개 이상인 상태에서는 비교 도구가 나타나는지 확인한다.
4. 정확히 2개만 선택할 수 있고 V15/V16 비교 화면이 유지되는지 확인한다.

## 3. 추가 정보 후보

1. 추가 정보가 필요한 후보가 포함된 portfolio를 연다.
2. 후보가 처음부터 큰 textarea form이 아니라 사업안명·한 줄 설명·확인 내용·확인 이유로 compact하게 보이는지 확인한다.
3. `정보 입력해서 검토 계속`을 누른다.
4. 해당 후보 편집기만 열리고 textarea가 부모 배경과 명확하게 구분되는지 확인한다.
5. 값을 입력하고 제출해 continuation이 기존 API로 이어지는지 확인한다.
6. 지원되지 않는 질문에서는 영어 raw question, textarea, 제출 버튼, `다른 방향 다시 탐색`이 보이지 않는지 확인한다.
7. 다른 준비된 사업안의 선택은 계속 가능한지 확인한다.

## 4. Decision surface와 forward scroll

1. 사업안을 선택한다.
2. 페이지 중간 scroll 위치가 유지되지 않고 화면 시작에서 선택 요약과 기준값 단계를 확인할 수 있는지 본다.
3. `현재 값으로 진행` 후 법률 결과도 page top에서 시작하는지 확인한다.
4. `시장 분석 준비하기` 후 `?view=validation-prep` 화면도 page top에서 시작하는지 확인한다.
5. 법률 PDF와 시장 분석 route도 첫 화면이 top에서 시작하는지 확인한다.
6. Project Settings Sheet를 열었다 닫았을 때 배경 페이지 scroll은 유지되는지 확인한다.
7. rationale → 선택 요약 → 기준값 → 법률 workspace 사이 간격과 surface 대비가 충분한지 확인한다.

## 5. Scroll-to-top

1. 긴 프로젝트 페이지에서 700px 이상 내린다.
2. 우측 하단에 위쪽 화살표 버튼이 나타나는지 확인한다.
3. Work Center나 다른 floating UI를 가리지 않는지 확인한다.
4. 버튼을 누르면 맨 위로 이동하는지 확인한다.
5. 390px 화면에서 safe area와 겹치지 않는지 확인한다.
6. OS의 reduced motion을 켜면 부드러운 이동 없이 즉시 이동하는지 확인한다.

## 6. 법률 결과 실행 체크사항

1. 법률·규제 결과 화면을 연다.
2. 종합 결과 바로 아래 `사업 진행 전 확인할 내용`이 보이는지 확인한다.
3. 필요한 조치, 고객 안내, 외부 협의·자격, 피해야 할 표현, 추가 확인사항이 기존 Legal Report 내용과 일치하는지 확인한다.
4. 임의의 높음/중간/낮음 또는 우선순위가 추가되지 않았는지 확인한다.
5. raw enum, content hash, source hash가 보이지 않는지 확인한다.

## 7. PDF와 기본 제안 파일명

1. `법률·규제 보고서 PDF`를 연다.
2. report cover가 페이지 상단에서 시작하는지 확인한다.
3. `PDF로 저장`을 누르고 Chrome/Edge 인쇄 미리보기를 확인한다.
4. `본문으로 바로가기`, app topbar, project header, action button, Scroll-to-top이 PDF에 포함되지 않는지 확인한다.
5. 3번 `실행 체크사항`이 보고서 초반에 포함되는지 확인한다.
6. 제안 파일명이 `{사업안명}_법률규제_사전검토_보고서_{YYYYMMDD_HHmm}` 형태인지 확인한다.
7. 사업안명에 `/`, `:`, `*` 등이 있어도 제안 파일명에 Windows 금지 문자가 없는지 확인한다.
8. 인쇄 창을 닫은 뒤 브라우저 문서 제목이 일반 서비스 제목으로 복원되는지 확인한다.

브라우저 Save-as-PDF 정책에 따라 최종 파일명은 사용자가 저장 창에서 변경할 수 있으며 앱이 OS 파일명을 강제하지는 않는다.

## 8. 사업 검증 준비와 BM Plan 초안

1. 법률 결과에서 `시장 분석 준비하기`를 누른다.
2. heading이 `사업 검증에 사용할 운영 정보를 준비하세요`인지 확인한다.
3. Market Research 직접 입력이 아니라 이후 사업 모델 캔버스 구체화에 사용하는 정보라고 이해되는지 확인한다.
4. `모든 항목은 선택 입력입니다` 안내가 한 번만 제시되는지 확인한다.
5. 선택 사업안에 operatingModel/transactionFlow 등이 있으면 활동·자원·파트너에 `선택한 사업안에서 가져온 초안`이 보이는지 확인한다.
6. 초안이 자동 입력되지 않고 `이 내용 사용`을 눌러야 현재값이 되는지 확인한다.
7. 적용 후 `수정`을 눌러 내용을 바꾸고 저장한 뒤, 사용자 수정값이 그대로 유지되는지 확인한다.
8. 고객 관계에는 자동 초안이 없고 직접 입력만 가능한지 확인한다.
9. 예산·기간·인원에 임의 숫자가 채워지지 않는지 확인한다.
10. 390px에서 resource field가 1열이며 horizontal overflow가 없는지 확인한다.

## 9. 회귀 확인

- V17 Legal PDF route와 market seed handoff가 유지된다.
- V16 재선택 후 gallery collapse가 유지된다.
- exact-two 비교와 Legal evidence grouping이 유지된다.
- Work Center Quick/Full 상호 배제, portal, body scroll lock, history가 유지된다.
- Hypothesis/Market canonical hash와 lineage 계약이 유지된다.
- BM Plan 저장 실패 시 market seed handoff가 호출되지 않고 입력이 유지된다.
