# 05. AI 파이프라인

> ⚠ **첫 줄에 못 박는다: 이것은 RAG가 아니다.**
> `embedding` · `pgvector` · `faiss` · `chroma` · `retriever` 전부 저장소 그렙 **0건**.
> 벡터DB에 문서를 미리 넣어 두고 꺼내 쓰는 구조가 아니라,
> **질문마다 실시간으로 웹·공공API를 수집하고 값에 출처를 붙이는** 파이프라인이다.
> 발표에서 쓸 말: **"수집·검증형"**, **"근거 부착형 조사 엔진"**.

---

## 1. 시장조사 엔진 (`ai/app/research/research2/`)

### 1-1. 5단계

```
[설계]  무엇을 조사할지 "슬롯"을 짠다        blocks/a_design.py + harness/slot_harness.py
   ↓
[수집]  슬롯마다 문서를 모은다               adapters/{web,kosis,dart,doc_window}.py
   ↓
[발췌]  문서에서 값과 인용문을 뽑는다        blocks/a_desk.py
   ↓
[검증]  출처·단위·자릿수·일관성을 검사       harness/gate.py + rules/*.json
   ↓
[성적표] 7과목으로 채점                     tools/scorecard.py
```

### 1-2. 슬롯 — 이 엔진의 최소 단위

슬롯 하나가 **하나의 답할 수 있는 질문**이다.

| 필드 | 뜻 | 예 |
|---|---|---|
| `subject` | 무엇에 대해 | "냉동 간편식" |
| `metric` | 무엇을 재는지 | "거래액" |
| `period` | 언제 | "2025" |
| `unit` | 단위 | "원" |
| `region` | 어디 | "대한민국" |
| `must_contain` | 본문에 반드시 있어야 할 낱말 | `["도시락"]` |
| `value_range` | 값의 기대 범위 | `[1e8, 2e9]` |

**슬롯을 사람이 아니라 하네스가 스스로 짠다**는 것이 이 엔진의 설계 축이다.
그리고 그 설계를 다시 기계가 검사한다(§2).

### 1-3. 수집 어댑터 4종

| 어댑터 | 원천 | 성격 |
|---|---|---|
| `web.py` | **Tavily** 웹 검색 + `trafilatura` 본문 추출 | 넓지만 품질 편차가 크다 |
| `kosis.py` | **KOSIS 국가통계** API | 표 실재를 대조할 수 있다 (`stat_code`) |
| `dart.py` | **DART 전자공시** API | 기업 매출 등 공시 원자료 |
| `doc_window.py` | PDF·문서 창 | 업로드 문서 |

> 실측(판㉛): **웹은 발췌에 들어간 44건 중 인용이 1건(2.3%)** 이었고,
> **KOSIS·DART는 문서 4건이 전부 인용까지 갔다(100%)**. 원천마다 성질이 다르다는 것을 수치로 안다.
> ⚠ 공공 API는 응답이 구조화돼 있어 **발췌 단계를 아예 거치지 않는다** — 분모가 다르다.
> 그리고 100%는 「인용까지」의 수율이고 채택은 kosis 3 · dart 0이다.

### 1-4. 성적표 7과목

문턱은 **코드가 아니라 `rules/fill.v2.json`에서만** 온다.

| # | 과목 | 문턱 |
|---|---|---|
| 1 | 시장 크기 | 관측 1건 |
| 2 | 성장률 | 2년치 · 직접률 · proxy선언 중 하나 |
| 3 | 경쟁사 | 실명 + URL 1곳 |
| 4 | 가격 | 표시가격 1건 (밴드를 그리려면 2건부터) |
| 5 | 수요 | 정량 1건 또는 정성 2건 |
| 6 | 계산(TAM) | TAM 산출 + **가정 명시 필수** |
| 7 | **못 찾은 것** | **항상** |

각 칸은 `채워짐 / 부분 / 미확보` 3값.

> ⭐ **발표에서 가장 강한 한 장이 될 수 있는 지점.**
> 이 규칙 파일에는 문턱을 바꾼 이유가 주석으로 남아 있다. 예를 들어 3번 경쟁사는
> 도메인 2곳 → 1곳으로 낮췄는데, 그 이유가 이렇게 적혀 있다:
>
> > *"「채웠는가」와 「몇 겹으로 확인했는가」는 다른 물음이다. 도메인 2곳을 요구하면
> > 관측이 1건 있는데도 칸이 「미확보」로 나가 사용자가 자료가 없는 줄 안다.
> > 확실성은 등급이 표기한다."*
>
> 그리고 4번 가격에는 이렇게 적혀 있다:
>
> > *"⚠ 가격 밴드 규칙은 건드리지 않았다. 1건으로 「밴드」를 그리면 밴드가 거짓이 된다.
> > 성적표가 묻는 것은 「이 칸에 쓸 값이 있는가」이고 밴드가 묻는 것은 「구간을 그릴 수
> > 있는가」다 — 두 물음의 답이 달라도 된다."*
>
> **문턱을 낮추면서 무엇을 낮추지 않았는지까지 파일에 남긴 것**이 이 프로젝트의 태도다.

### 1-5. 규칙 파일 23개

`rules/` 아래 JSON 23개가 파이프라인의 모든 판단 기준을 갖는다.

`fill.v2`(성적표 문턱) · `scoring.v1`(점수) · `guards.v1`(계량 전형 밴드) ·
`units.v1`(단위) · `consistency.v1`(일관성) · `slotcheck.v1`(슬롯 검사) ·
`trust_labels.v1`(등급) · `source_signature.v1`(출처 서명) · `whitelist.v3~v8`(도메인 화이트리스트) 등

**설계 원칙: 문턱은 코드에 있으면 안 된다.**
판㉛에서 실제로 이 원칙을 어긴 곳 2개(성장률·계산)를 찾아 규칙 파일로 옮겼다 —
*"문턱을 고쳐도 표가 안 따라왔다"*는 것이 발견의 계기였다.

## 2. 하네스 — 설계를 기계가 검사한다

`harness/` — 슬롯 설계가 나오면 **수집을 시작하기 전에** 검사한다.

| 파일 | 하는 일 |
|---|---|
| `slot_harness.py` | 슬롯 생성 루프 |
| `gate.py` | 게이트 검사 — 통과 못 하면 다시 설계 |
| `vocab.json` | 어휘·라우팅 정본 (계량 → 어댑터, BM 캔버스 칸 라우팅) |
| `doc_intake.py` / `tavily_intake.py` | 문서 반입 |

**왜 중요한가** — 유료 수집을 태우기 전에 설계 품질을 무료로 거를 수 있다.
`tools/design_score.py`와 `tools/slot_dryrun.py`가 그 판정을 하고 **둘 다 LLM 0회**다.

⚠ 다만 **필요조건이지 충분조건이 아니다.** 실측: `must_contain=["도시락"]`이 규율을 지키고도
「쌀의 날 행사 할인가 1,000원」을 통과시켰다. 행사 할인가는 시장가가 아니다.

## 3. BM 캔버스 — 9칸의 두 성격

정본: `harness/vocab.json`의 `canvas` 라우팅 표.

| 성격 | 칸 | 요건 |
|---|---|---|
| **측정·판정 (4칸)** | 고객 세그먼트 · 가치 제안 · 채널 · 수익원 | 담당 조사 슬롯 ≥ 1 |
| **계획 (5칸)** | 고객 관계 · 핵심 자원 · 핵심 활동 · 핵심 파트너 · 비용 구조 | **슬롯 불필요** |

**계획 칸 재료의 우선순위**: `사용자 입력 > 견본 스텁 > 컨셉 파생`

⭐ **`_`로 시작하는 키는 수집 프롬프트로 새지 않는다.**
사용자가 쓴 계획이 수집에 들어가면 모델이 **그 계획을 확인해 주는 자료만** 찾아오는
**자기확인 회로**가 된다. 그래서 `run.py`의 `load_concept`이 `_` 키를 걸러낸다.
같은 이유로 `hypotheses`도 비운다.

> 발표에서 이 한 줄이 강하다: **"우리는 AI에게 우리 가설을 안 알려준다."**

**사용자가 쓴 칸은 기계로 `PLAN` 도장을 찍는다.** 근거 인용이 0인 칸은 도장을 내리고
"사용자가 입력한 실행 계획이다 — 관측이 아니다"를 경계에 더한다. **내리는 방향만 한다.**

## 4. 패널 트윈 조사 (`ai/app/twin/`)

```
트윈 카드 뱅크 → 조건에 맞는 가상 응답자 추출 → 자극 제시 → 응답 → 집계 → 대표 응답자 카드
```

| 구성 | 파일 |
|---|---|
| 뱅크 | `twin_cards_generic.jsonl` (11MB) · `twin_frame.csv` · `twin_bank_manifest.json` |
| 실행 | `runner.py` · `aggregate.py` |
| 자극 | `stimuli.py` · `stimulus_draft.py` (초안 자동 생성) |
| 경계 | `caveats.py` |

**뱅크의 근거** — 한국미디어패널조사 원자료에서 파생. K-Means 5축 클러스터링으로
세그먼트(연령대×성별) 14개를 만들었다. 표본 **8,355명**, 예: "50대 여자" n=1,067 · k=5 ·
silhouette **0.281**. (`model/rebuild/persona_5axis.py`, `random_state=42`)

⚠ 뱅크 자체는 **재배포 금지 자산**이라 git에 커밋하지 않는다(`.gitignore`).

### 경계 문구 (지우면 안 된다)
> **"가설이며 실제 고객 응답이 아니다."**

과거 설계의 「페르소나 → 인터뷰 → 종합」 체인은 없어졌고 이 조사가 그 자리를 대신한다.

## 5. 법률 검토 (`ai/app/legal/`)

**법제처 Open API(`law.go.kr/DRF`) 실연동.** 모델이 법을 지어내지 않는다.

| 파일 | 역할 |
|---|---|
| `pipeline.py` | 법률 사전검토 / 컨셉 법률 검증 파이프라인 |
| `concept_validation.py` | `GUARDRAIL`(단건) / `GUARDRAIL_BATCH`(배치) 모드 |
| `moleg.py` | 법제처 Open API 클라이언트 |
| `registry.py` | 법령 레지스트리 |

**설계(DEC-009 / DEC-019)**: 법제처 API가 법령 원문·식별자·현재성 확인의 authoritative source다.
한쪽이 실패하면 **degraded result로 표시**하고, 출처·조회 시각·법령 식별자·조문·source channel과
`EXPERT_REVIEW_REQUIRED`를 함께 반환한다.

### 경계 문구
> **"법률 자문이 아니다."**

## 6. 프롬프트를 보여준다 (PIILOT p17 기법)

PIILOT은 "LLM 썼습니다" 대신 **프롬프트 원문을 슬라이드에 붙여** 어떤 제약을 걸었는지 보여줬다.
우리도 같은 것을 할 수 있다. 후보:

- **절대 규칙 6 — 가설 누출 금지**: 사용자의 가설이 수집 프롬프트에 들어가지 않게 하는 규칙
- **규칙 7 — `must_contain`은 가를 것이 없으면 빈 배열**
- **BM 프롬프트 §5 — "명시된 것만"**: 컨셉에 없는 것을 유추해 채우지 못하게 하는 규칙
- **BM 프롬프트 §9 — "실제 파트너 정보가 있을 때만"**

전부 **"AI가 지어내지 못하게 막는 제약"**이라는 하나의 주제로 묶인다.
