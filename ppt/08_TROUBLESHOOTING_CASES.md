# 08. 트러블슈팅 케이스 ⭐

> PIILOT 덱에서 심사 배점이 가장 컸던 파트는 Redis 캐싱 **5장 연속 케이스 스터디**였다.
> 구조가 이랬다:
> `① 과제 정의 → ② 대안 A/B 각각의 문제점 표 → ③ 채택 아키텍처 → ④ 코드 → ⑤ 성능표 + 트레이드오프표`
>
> **케이스 1을 그 5장 구조로 쓴다.** 케이스 2·3은 요약 1장으로 붙인다.
> 원천은 `docs/CONCEPT_TO_RESEARCH_HANDOFF.md` §16–§17 (git 추적됨).

# 케이스 1 — "찾아놓고 버린 것을 되찾았다" (5장)

## [1/5] 과제 정의

**증상**: 시장조사 성적표 7과목 중 **4과목이 동시에 미확보**로 나왔다.
①시장크기 ②성장률 ③경쟁사 ⑥계산. blocker 위반도 1건(R9).

**첫 진단은 틀렸다.** 자연스러운 해석은 "자료가 없다"였다.
실제로 사용자에게는 **빈 슬롯으로만 보이고**, 원장에도 빈칸으로 남는다.

**진짜 원인**: 검색은 **옳은 문서와 옳은 값을 물어왔는데**,
슬롯의 `value_range`(값 기대 범위)가 **4자릿수 작아서 전부 격리**되고 있었다.

| 슬롯 | 실제 값 | 기대 범위 | 자릿수차 | 원천 |
|---|---|---|---|---|
| S1 거래액 | 3.80e13 (**38.0조**) | [1e8, 2e9] | 4.3 | KOSIS `DT_1KE10041` |
| S5 거래액 | 3.48e13 (34.8조) | [1e8, 2e9] | 4.2 | KOSIS |
| S6 거래액 | 3.02e13 (30.2조) | [8e7, 1.8e9] | 4.2 | KOSIS |
| S7 매출액 | 2.73e13 (**27.3조**) | [1e8, 1.5e9] | 4.3 | DART CJ제일제당 |
| S8 매출액 | 3.67e12 | [8e7, 1.3e9] | 3.5 | DART |
| S9 매출액 | 2.53e12 | [6e7, 1.2e9] | 3.3 | DART |

**자료 부재가 아니라 찾아놓고 버린 것이다.**

### 왜 아무 검사도 이걸 못 잡았나

| 검사 | 보는 것 | 왜 통과시켰나 |
|---|---|---|
| `gate.check_value_range` | 상한 > 하한 | 상한이 하한보다 크긴 하다 |
| `slot_dryrun.check_guards` | 범위 폭이 10배 미만인지 | [1e8, 2e9]는 **20배**라 통과 |
| `design_score` | 설계 4축 | **자릿수를 안 본다** (넣지 않았다) |

**그리고 라벨 데이터에도 이 축의 신호가 없었다.** 기준 스냅샷 9판 전부 사람이
`value_range`를 적었고 자릿수가 맞았다.
→ **재는 자를 라벨에서만 뽑으면, 라벨이 안 흔든 축은 구조적으로 못 만든다.**

## [2/5] 대안 비교

| | 방법 A — 슬롯 밴드를 차단 필터로 강화 | 방법 B — 프롬프트로 밴드를 잘 적게 시킨다 |
|---|---|---|
| 방식 | 값이 밴드 밖이면 무조건 격리 (지금 동작) | 하네스 프롬프트에 "자릿수를 맞춰라"를 추가 |
| 문제 1 | **밴드 자체가 틀리면 옳은 값을 계속 버린다** — 지금 겪고 있는 바로 그 증상 | 모델이 규칙을 무시해도 **알 방법이 없다** |
| 문제 2 | 필터가 새 검열자가 된다. 이 파일 첫 줄이 금하는 것 | 실측: 규칙 7-0과 분량을 둘 다 적었는데 모델이 1개만 냈다. **권고는 떴지만 `passed=True`라 재시도가 안 걸렸다** |
| 문제 3 | "크기 필터로 종류 오류를 거른다"는 잘못된 습관을 굳힌다 | 재현성 없음 — 반복 3회에서 검사별 미통과 0.167~0.333으로 흔들린다 |
| 결론 | ✕ 원인을 강화하는 꼴 | ✕ 검증할 수 없는 개선 |

**두 방법 모두 구조적 한계** → **계량별 "전형 밴드" 표를 두고 두 층이 같이 읽게 한다.**

## [3/5] 채택 설계

`rules/guards.v1.json`에 **계량 전형 밴드** 표를 두고 **두 층이 같이 읽는다.**

```
[수집 층]  blocks/a_desk.off_slot_reason
   값이 슬롯 밴드 밖이어도  →  계량 전형 밴드 안이면  →  격리하지 않는다
                                                        "기대_밖.구조됨" 으로 남긴다
[설계 층]  harness/gate.check_range_band
   슬롯 밴드가 전형 밴드와 안 겹치면  →  권고 (막지 않는다)
```

### ⭐ 왜 `vocab.json`이 아니라 `rules/`인가

`blocks/`는 유리벽 안이라 `harness/vocab.json`을 **안 읽는다.**
반대로 하네스는 `rules/`를 직접 읽는다. **양쪽이 볼 수 있는 자리는 여기뿐**이다.

표가 갈리면 **"설계는 통과인데 수집이 버린다"**가 생긴다.
(계획서는 `vocab`이라고 적었고 **그것이 틀렸다.**)

### ⭐ 비대칭이 의도다

- 밴드 **안**이면 → **살린다**
- 밴드 **밖**이어도 → **차단하지 않고 표시만** 한다

> 차단까지 하면 이 표가 **새 검열자**가 되고, 그것이야말로 이 문제의 원인이었다.

## [4/5] 구현

핵심은 세 곳이다.

```python
# ① rules/guards.v1.json — 계량별 전형 밴드
#    거래액·매출액은 조 단위. 문턱은 코드가 아니라 여기에만 있다.

# ② blocks/a_desk.py — 수집 층: 구조한다
#    슬롯 밴드 밖 → 전형 밴드 안이면 격리하지 않고 '기대_밖.구조됨' 으로 남긴다

# ③ harness/gate.py — 설계 층: 권고만 낸다
#    check_range_band(): 슬롯 밴드 ∩ 전형 밴드 == ∅ → 권고 (passed 는 True 유지)
```

같은 판에서 곁가지 2건도 함께 고쳤다.

- **범위 쪼개기** (`a_desk.split_range()`): 「2,400~3,400원」을 **하한·상한 각각의 사실로** 낸다.
  대표값(중간값)을 만들면 **원문에 없는 수를 지어내는 것**이다.
  ⚠ 원래 갈래마다 다르게 틀렸다 — `number_raw`면 조용히 **하한만**(플래그도 없다),
  `unit_raw`면 **null**. **조용한 쪽이 더 위험했다.**
  ⚠ 한국어 배수(만·억)는 **수의 일부**다. 「10만~30만」에서 「만」을 단위로 떼면 양쪽 다 죽는다.
- **단위 재선택** (`a_desk.reread_for_unit()`): 모델이 고른 수의 단위가 슬롯과 안 맞으면
  **인용 한 문장 안에서** 다시 읽고, `Fact.수_재선택`에 **덮었다는 사실을 남긴다.**
  ⚠ **인용 밖은 안 본다.** 문서를 뒤지면 `quote_verified`가 뜻을 잃는다.

> ⚠ `parse_number`의 **시그니처는 안 건드렸다** — `cases_numbers.json` 50건이 그 계약 위에 있다.

## [5/5] 결과와 트레이드오프

### 결과 — **LLM 0회, 비용 0원**

같은 원장(`p32-auto01`)을 재채점만 했다. **새로 산 자료는 한 건도 없다.**

| 항목 | 전 | 후 |
|---|---|---|
| **성적표** | **2/6** | **6/6** |
| 확인됨 | 0 | **6** |
| 격리 | 13 | **3** |
| 충족 슬롯 | 3/15 | **9/15** |
| blocker 위반 | 1 (R9) | **0** |

부수 효과: S14가 배달비 밴드를 통째로 냈다 —
1,900 / 2,100 / 2,130 / 2,400 / 2,900 / 3,100 / 3,130 / 3,400원.

### 트레이드오프 — 알고 남긴 것

| 트레이드오프 | 영향 | 대응 |
|---|---|---|
| **슬롯 밴드 자체가 틀리면 그물이 헛돈다** | 「38조를 100만 배 축소한 3.8e7」은 틀린 밴드 옆에 붙어 **자릿수차 0.42**로 그냥 지난다 | **막지 않고 `전형_밴드_밖`으로 표시만** 한다 |
| 전형 밴드 표를 사람이 관리해야 한다 | 계량이 늘면 표도 늘어야 한다 | 규칙 파일이라 코드 배포 없이 고칠 수 있다 |
| 설계는 여전히 스스로 못 고친다 | 권고가 **재시도를 안 건다** | 미해결. 다음 판의 과제로 남김 |
| 새 게이트 검사는 **권고**다 | 막지 않으므로 나쁜 설계가 통과할 수 있다 | 막았으면 **승인된 골든이 19건 걸려 소급 무효**가 됐다 |

### 곁가지로 드러난 것 — 성적표만 보면 안 된다

범위 쪼개기가 밴드 값을 늘리자 **R11(같은 지표 두 값, blocker)**이 떴다.
파 보니 **기준 스냅샷 `pin-09`의 실행도 원래 R11을 위반하고 있었다.**

> **아무도 못 본 이유는 성적표가 체인 위반을 안 보여주기 때문이다.**

그래서 "가격은 모순이 아니라 밴드다"라는 판단으로 `consistency.v1.json`에
`밴드_claim_type: [PRICE, ALT]`를 두고 그 축만 뺐다.

# 케이스 2 — 병목은 검색기가 아니라 발췌였다 (1장)

| | 내용 |
|---|---|
| **가설** | 시장조사가 자료를 못 찾는 이유는 검색기(Tavily)가 나쁘기 때문이다 |
| **측정** | `tools/funnel.py` 신설 — 단계별 유입/유출/유실 사유를 코드가 센다 (LLM 0회) |
| **결과** | 병목은 **발췌(extract)** 였다. 웹 문서 **44건 → 인용 1건 (2.3%)**. 같은 판에서 **KOSIS·DART는 4/4 (100%)** |
| **교훈** | **원천마다 성질이 다르다.** 웹은 넓지만 발췌가 어렵고, 공공 API는 좁지만 구조가 있다 |
| **조치** | 0~6단계 수리. **본문 도달률 54.1% → 87.3%**, 성적표 3·0·3 → 4·0·2 |
| **남은 것** | 발췌 호출이 12회 → 53회로 늘어 검색 24회와 합쳐 **77회**(한도 90). 유료 실측 시 예산 관리 필요 |

> 발표 한 줄: **"손으로 세지 말고 코드가 세게 했다."**
> 도구를 만들기 전까지 우리는 잘못된 곳을 고치고 있었다.

# 케이스 3 — 성적이 좋은데 틀린 답 (1장)

| | 내용 |
|---|---|
| **문제** | 성적표(`scorecard.py`)는 수집 **결과**를 잰다. 설계가 나빠도 **검색이 운 좋으면 높게 나온다** |
| **증거** | `pin-06`이 성적표 **6/6인데 오답**이었다 |
| **조치** | `tools/design_score.py` 신설 — **설계**를 기준 스냅샷과 대조. 4축(서식지_분산 · must_contain_규율 · 발행_가능성 · 계열_가격어휘), LLM 0회 |
| **의도된 불일치** | `design_score`는 `pin-07`(성적표 4/6)을 `pin-06`(6/6)보다 **높게** 매긴다. **성적표와 갈리는 것이 이 도구의 존재 이유다** |
| **한계 (자진 노출)** | **필요조건이지 충분조건이 아니다.** 네 축 만점이어도 오답이 통과한다 — `must_contain=["도시락"]`이 규율을 지키고도 「쌀의 날 행사 할인가 1,000원」을 통과시켰다. 행사 할인가는 시장가가 아니다 |
| **곁가지 발견** | `판매가`가 `vocab.metric._가격_계량` 표에 **없었다**. 앞 판에서 catalog에만 넣고 이 표를 안 고쳐서, 계열 C 가격 계량이 강제도 검사도 안 받고 있었다 |
| **적용 규율** | 유료 수집을 태우기 전에 `design_score` + `slot_dryrun`을 먼저 돌린다. **둘 다 무료다** |

## 발표 시 주의

1. **"자료가 없었다"가 아니라 "우리가 버렸다"로 말한다.** 이 케이스의 힘은 자기비판에 있다.
2. **비용 0원을 강조한다.** LLM을 한 번도 더 부르지 않고 2/6 → 6/6을 만들었다.
3. **트레이드오프 표를 빼지 않는다.** PIILOT이 심사에서 강했던 이유가 그것이다.
4. 케이스 1의 [2/5] 대안 비교는 **실제로 검토하고 기각한 것**이다. 사후에 지어낸 대안이 아니다.
